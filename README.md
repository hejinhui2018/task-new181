# ClauseHarbor · 保险产品条款审核交付台

面向产品法务的条款评审工作台：维护条款与版本、术语定义引用、产品与地区覆盖；
按**评审轮次**组织地区意见；自动核对定义、责任范围、生效日期与地区覆盖冲突；
通过的条款组成**发布包**并生成冻结回执，未通过或缺依赖的内容留在**隔离区**。

- 纯 Node.js（≥ 20）实现，零外部依赖、零构建步骤
- 前端为原生 HTML/CSS/JS 单页，后端为 `node:http` + JSONL WAL + 快照持久化

## 启动

```bash
npm start                 # 默认 http://localhost:3000，数据在 ./data
PORT=8080 CH_DATA_DIR=/var/lib/clauseharbor npm start
npm test                  # 运行 25 个自动化回归用例
```

首次打开点击右上角 **「载入演示数据」**，即可得到一套覆盖完整业务故事的示例：
2 个产品、3 个地区、3 个术语、2 轮评审、1 个已移交发布包、5 条隔离内容与若干冲突。

## 七个工作视图

1. **总览** — 条款/冲突/发布包关键指标、最近轮次动态、回执漂移一览。
2. **条款库** — 新建条款、反复保存草稿、提交、撤回、补交、发起替换；版本谱系可逐条展开。
3. **评审轮次** — 轮次时间线；每轮各地區结论独立成行；关闭轮次后结论**冻结**，只能在新一轮提交新版本。
4. **冲突与准备度** — 条款 × 地区准备度矩阵；定义缺失、责任互斥、生效日期不一致、地区缺口四类核对结果。
5. **发布中心** — 可发布条款勾选组包；不合格条款与拦截原因进隔离区；移交后生成回执号。
6. **定义 / 产品 / 地区** — 术语库维护、产品销售地区覆盖配置。
7. **系统与恢复** — WAL 序号、审计日志、异常恢复事件；可一键注入「快照损坏 / WAL 截断」故障并重新装载验证恢复。

## 核心业务规则

### 版本与轮次（旧结论永远不能覆盖新结论，反之亦然）

- 条款始终区分 `currentVersionId`（当前生效通过版）与 `openVersionId`（在途版）。
- **草稿**可反复保存，不进入任何轮次；提交后只能在所属轮次开放期间撤回。
- **退回 / 拒绝后补交**：系统**新建版本**进入当前轮，被退回版本与其地区意见原样冻结在旧轮。
- **替换已通过条款**：新版本在审期间旧版本仍为生效版；替换通过则旧版归档为 `superseded`；
  替换件被退回、拒绝或撤回时，旧版本**自动恢复**为当前版本。
- 地区评审只能写入「当前开放轮次中、条款最新在途版本」；关闭轮次或新版本接管后，旧记录一律 409 拒绝改写。
- `pending`（待结论）不算地区已回复，齐审判定只认 approved / returned / rejected / waived。

### 冲突核对

| 类型 | 级别 | 含义 |
|---|---|---|
| `missing_definition` | 草稿预警 / 提交后阻断 | 引用了术语库中不存在的定义编码 |
| `definition_drift` | 提示 | 正文内联 `{{DEF:CODE=文本}}` 与术语库当前文本不一致 |
| `effective_date_mismatch` | 提示 | 同一产品下非草稿条款生效日期不一致（以多数日期为基准，只标异日方） |
| `scope_conflict` | 含草稿为提示 / 双方生效后阻断 | 责任标签 `#项目` 与 `#-项目` 在同产品条款间互斥 |
| `region_gap` / `region_review_missing` | 提示 | 产品未配地区 / 条款缺所需地区的评审结论 |

### 发布包、隔离区与回执

- 只有 `approved_current`、无 error 级冲突、所需地区全部 approved/waived 的条款可入包。
- 混选时合格条款入包，不合格条款列入包内 `rejected` 清单并留在隔离区，附具体拦截原因。
- 同一发布包内生效日期必须一致，否则整组拒绝组装。
- 移交生成 `RCPT-xxxxxx-YYYYMMDD` 回执号；**回执是版本快照**（正文、引用、地区意见、通过轮次均冻结），
  条款后续改版不会改动回执，只在回执上产生「漂移提示」。

### 持久化与异常恢复

```
写命令：状态副本执行校验+捕获ID/时间序列 → 追加 WAL(append) → 提交内存
重启：  snapshot.json (+ snapshot.prev.json) + 重放 wal.log 中 seq 更新的记录
```

- WAL 为 JSONL，每条记录包含参数与该命令内部生成的全部 ID/时间戳，重放后实体 ID 逐字节一致，跨重启引用不断。
- 快照采用 `tmp + rename` 原子写，并保留**上一代快照**；WAL 截断点滞后一代，当前代快照损坏时可回退上代 + 增量重建。
- WAL 末尾半截行（崩溃写一半）自动跳过、记录 `wal_truncated` 并重写干净 WAL。
- 快照损坏自动隔离为 `*-corrupt-<时间戳>.json` 并记录恢复事件；无法安全重放的日志报 `replay_failed`，绝不伪造状态。
- 非法命令在副本上即失败，WAL 不会留下记录。

## 目录结构

```
src/domain.js       领域模型：版本状态机、轮次冻结、冲突引擎、准备度、发布包（无 IO 依赖，可单测）
src/persistence.js  Store：WAL + 双代快照 + 重放恢复
src/server.js       HTTP 服务：静态资源与 /api（state / dispatch / seed / checkpoint / fault / reload）
src/seed.js         演示数据
public/             前端单页（index.html / app.js / styles.css）
test/               node:test 回归：领域 13 例、持久化 10 例、HTTP 端到端 2 例
```

## API 摘要

- `GET  /api/state` — 全量派生视图（条款、时间线、冲突、准备度矩阵、隔离区、回执、审计、恢复事件）
- `POST /api/dispatch` — body `{type, args}`，执行一条领域命令并返回最新视图；业务冲突返回 4xx
- `POST /api/seed` — 追加载入演示数据
- `POST /api/checkpoint` — 立即生成快照并压缩 WAL
- `POST /api/debug/fault` `{kind: "corrupt_snapshot" | "truncate_wal"}` — 故障演练
- `POST /api/reload` — 不重启进程执行一次装载恢复流程
